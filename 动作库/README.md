# 人类训练体系：动作库

动作库中的每个动作独立保存为一个 Markdown 文件，统一放在本目录根部。动作不是孤立的“动作名称”，而是训练任务的载体；同一个动作在不同负荷、速度、幅度、支撑、感觉、认知和疲劳条件下，可能产生不同的主要适应。

动作库不按器械、肌肉或训练目标建立文件夹。因为一个动作往往同时涉及多个模块、多个器械变体和多个训练目标，目录分类会把动作强行归入单一角度。动作的多维属性统一通过文件头标签和正文分析表达。

## 3. 多维标签与动作条目

动作库根目录不再建立按器械或模块划分的子文件夹。所有动作采用“一动作一文件”：

```text
动作库/
├── README.md
├── 前脚掌承重脚趾抓取与释放.md
├── 箱式深蹲.md
├── 单车踩踏.md
└── 双手壶铃摇摆.md
```

文件头通过多个标签表达动作的不同层面，例如：

```markdown
> 器材：壶铃
> 标签：#髋主导 #爆发力 #力量耐力 #体能 #握力 #躯干控制 #后侧链 #周期性输出
```

标签可以描述：

- 器材：壶铃、单车、徒手、杠铃、哑铃、弹力带；
- 动作组织：蹲、髋折叠、推、拉、搬运、行走、旋转；
- 能力模块：力量、耐力、速度、爆发、活动度、平衡、反应；
- 结构视角：足部、踝、膝、髋、肩带、胸廓、脊柱、骨盆；
- 训练用途：恢复、基础、力量、力量耐力、体能、专项迁移；
- 训练条件：单侧、双侧、周期性、弹道、低冲击、认知双任务。

标签用于检索和建立多维关系，不能代替正文中的动作定义、执行细节和分析。

## 统一分析角度

动作分析至少回答：

- **目标角度**：为什么使用这个动作？
- **任务角度**：身体需要完成什么结果？
- **结构与力线角度**：足部、关节、骨盆、胸廓和脊柱如何承重、传力和调整？
- **能力模块角度**：主要能力、支撑能力和可能限制是什么？
- **训练条件角度**：负荷、动态、感觉、认知、环境和疲劳如何改变刺激？
- **执行角度**：哪些细节必须满足，哪些只是表现优化？
- **进阶角度**：怎样从可进入发展到可控制、可承载、可表现和可适应？
- **反馈角度**：如何判断动作质量、外部输出、认知表现、恢复和迁移？

## 动作文件命名

建议使用清晰的中文动作名，例如：

```text
高脚杯深蹲.md
行李箱走.md
低台阶上台阶.md
```

不要在动作库中把“深蹲 4×8”作为一个动作文件；组数、次数、重量和休息属于训练计划中的剂量，应在计划文件中引用动作库动作。

## 与训练计划的关系

- 动作库回答：这个动作是什么，如何分析和使用？
- 训练计划回答：本周哪一天为什么使用它，使用什么剂量和条件？
- 训练任务库回答：多个动作如何组成跨模块任务？

动作文件应保持相对稳定；计划文件记录具体个体、阶段和当天的训练处方。
